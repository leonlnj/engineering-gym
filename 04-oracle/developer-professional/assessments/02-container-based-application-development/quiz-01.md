## Answer key

1. OCIR has no registry-specific account system; every push/pull is authorized by ordinary compartment-scoped IAM policy, the same as any other OCI resource. Consequence: a valid credential alone never grants access — a policy grant is also required. — **Covered**: §1.1.
2. Region key (`<region-key>.ocir.io`, the regional endpoint) / tenancy namespace (auto-generated Object Storage namespace) / repository name (an OCID-bearing resource) / tag. — **Covered**: §1.2 anatomy breakdown.
3. Repository display names must be unique across every compartment in the entire tenancy, not just within their apparent "folder" — the slash is a naming convention, not a real hierarchy. — **Covered**: §1.2 Nuance box.
4. An Auth Token, a generated secret distinct from the Console password — kept separate so a leaked Docker config never exposes the primary login. — **Covered**: §2.1.
5. Federated users insert an extra `oracleidentitycloudservice` segment: `<namespace>/oracleidentitycloudservice/<username>`. — **Covered**: §2.1 snippet.
6. A Bearer Token (JWT) issued to a resource principal; unlike a long-lived Auth Token, it is short-lived, bounding leak exposure to hours. — **Covered**: §2.2.
7. When the caller's identity originates entirely outside OCI's principal system (workload identity federation, an external CI system) and needs token exchange to get in at all. — **Covered**: §2.2 selection guidance.
8. A tag is a mutable pointer; repushing `:latest` silently repoints it, so a manifest naming `:latest` can pull different content tomorrow with no manifest change — breaking twelve-factor X, dev/prod parity. — **Covered**: §3.2.
9. A tag is reassignable; a digest (`sha256` of the manifest) is permanent and content-addressed. Production manifests should reference the digest. — **Covered**: §3.1, §3.4, reinforced in §6.2.
10. Immutability blocks any push that would overwrite an existing tag in that repository, including an intentional floating-pointer update — the workaround is unique per-build tags plus keeping any floating pointer in a separate, non-immutable repository. — **Covered**: §3.3.
11. Exempt Versions only guards the "not pulled in N days" criterion; the "not versioned in N days" criterion targets untagged manifests, which have no version string for the exemption pattern to match. — **Covered**: §4.2 Nuance box.
12. The cooling-off period lets a bad policy edit (e.g., a wildcard typo) be caught before the hourly sweep acts on it; the up-to-48-hour deletion window is the time needed for actual deletion and storage reclamation. — **Covered**: §4.4.
13. A missing Kubernetes `imagePullSecret` — OKE's pull mechanism is defined by the Kubernetes API, not OCI's IAM model, so same-tenancy/region access never waives the explicit secret requirement. — **Covered**: §5.2 Nuance.
14. Functions authenticates as a first-class OCI resource principal under ordinary IAM policy with no pull secret; OKE's pull path runs through the Kubernetes API, which has no native concept of an OCI resource principal, so it needs an explicit secret instead. — **Covered**: §5.2 closing paragraph.
15. The 500 GB/region storage quota and the 100,000-images/repository quota. A lightweight service image is more likely to hit the image-count ceiling first; a heavy image is more likely to hit the storage ceiling first. — **Partial**: §1.3 and Practical Limits state the direction for large images ("hits the storage ceiling ... if its images are large") but never spell out the reverse case (small images hitting the count ceiling first) explicitly.

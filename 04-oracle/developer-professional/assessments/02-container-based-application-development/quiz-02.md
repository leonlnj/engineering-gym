## Questions

1. Two engineers argue about whether OCIR is "just Docker Hub for OCI." What's the one architectural fact that makes this description wrong, and what follows from it for troubleshooting a permission problem? _(registry resource model · production-reasoning)_
2. Your tenancy namespace shows up in every OCIR image path. Where does that string actually come from — is it something OCIR generates for itself? _(registry path anatomy · exam-ready)_
3. Why is a slash in a repository display name (like `project01/acme-web-app`) a naming convention rather than a real folder hierarchy — what evidence proves this? _(repository naming · exam-ready)_
4. You rotate a colleague's Auth Token after they leave the team. What breaks for them immediately, and what does *not* change about the IAM policy governing their old access? _(auth token lifecycle · production-reasoning)_
5. Contrast an Auth Token with a Bearer Token (JWT) on exactly one axis: what happens to your exposure if each one leaks? _(auth mechanism trade-off · production-reasoning)_
6. A workload running entirely outside OCI (e.g., on another cloud) needs to pull from OCIR without ever holding a static OCI credential. Which of the three authentication mechanisms fits, and why do the other two not? _(auth mechanism selection · exam-ready)_
7. Explain, in terms of digests, why re-tagging an image with a semantic release name never requires rebuilding it. _(tags vs. digests · exam-ready)_
8. A repository is marked immutable, and a hot-fix build needs to replace what `:stable` currently points to. What does OCIR do, and what's the actual fix path? _(immutable repositories · production-reasoning)_
9. Why does OCI's own documentation and CLI call a tag a "version" — does this mean there are two different mechanisms, or one mechanism with two names? _(terminology · exam-ready)_
10. A retention policy's "not versioned in N days" criterion just deleted an image whose tag was in the Exempt Versions list. Is this a bug? Explain what's actually happening. _(retention criteria scope · exam-ready)_
11. Why would an OCI engineer deliberately build a several-hour delay into when a newly-edited retention policy starts taking effect? _(retention sweep timing · production-reasoning)_
12. A team wants an emergency purge of old images to free storage quota right now. What two OCI-imposed timing facts should temper that expectation? _(retention sweep timing · production-reasoning)_
13. A DevOps pipeline pushes to a repository path that doesn't exist yet, and a repository is auto-created — but a later pipeline run in the same compartment fails to see it under an IAM policy that should apply. What configuration explains the mismatch? _(pipeline integration · production-reasoning)_
14. Contrast how OCI Functions authenticates to pull an image from OCIR versus how an OKE pod does. Why does OKE need an extra step Functions doesn't? _(pipeline/consumer contrast · exam-ready)_
15. If OCIR enforced an image-count limit but no storage limit at all, would a team pushing one build image a day with no retention policy ever get blocked? Reason about which quota binds first as image sizes grow. _(quota reasoning · production-reasoning)_

## Answer key

1. OCIR authorizes every push/pull through ordinary IAM policy scoped to a compartment, not a separate registry account system — so a "permission denied" is an IAM policy problem, not a registry-account problem. — **Covered**: §1.1.
2. An auto-generated Object Storage namespace string already assigned to the tenancy; OCIR reuses it rather than minting its own. — **Covered**: §1.2.
3. Repository names must be unique across the whole tenancy, not just within their apparent "folder" — a real hierarchy would only require uniqueness inside the folder. — **Covered**: §1.2 Nuance box.
4. Their `docker login` sessions using that token stop working immediately; the IAM policy granting their group/user access to `repos` is untouched — a new token under the same identity would work again immediately once generated. — **Partial**: §2.1 states the token is valid "until you rotate or revoke it" and the Nuance box separates authentication (token) from authorization (policy), but the lesson never walks through this specific revocation scenario end to end.
5. An Auth Token is valid indefinitely until manually rotated/revoked, so a leak's exposure window is open-ended; a Bearer Token is short-lived by design, bounding exposure to hours. — **Covered**: §2.2, reinforced in Practical Limits.
6. A Security Token (UPST) via Workload Identity Federation — an Auth Token requires a human at a terminal, and a Bearer Token still assumes an existing API-key-based OCI principal, which an external workload doesn't have. — **Covered**: §2.2 selection guidance.
7. A digest can carry multiple tags simultaneously; re-tagging points a new name at the same existing digest, so no new bytes are produced. — **Covered**: §3.4.
8. OCIR rejects the push outright; the fix is to stop relying on a floating tag — use unique tags plus a separate non-immutable repository if a floating pointer is truly needed. — **Covered**: §3.3.
9. One mechanism, two names — OCI's CLI/console vocabulary calls it "version" (e.g., Exempt Versions, `--version` filter) while Docker's vocabulary calls the same thing a "tag." — **Covered**: §3.1 Note box.
10. Not a bug — Exempt Versions only guards the pull-age criterion; the versioned-age criterion has no version string to match against for an untagged manifest, so exemption never applies there. — **Covered**: §4.2 Nuance box.
11. To give an operator a window to catch a mistake (e.g., a bad wildcard pattern) in a policy edit before the hourly sweep starts acting on it. — **Covered**: §4.4.
12. The cooling-off period (several hours before a new/edited policy is even evaluated) and the up-to-48-hour window for a marked image's deletion and storage reclamation to complete. — **Covered**: §4.4 and Practical Limits.
13. `is-repository-created-on-first-push` creates the new repository in the tenancy's *root* compartment regardless of where the pipeline runs, so a policy scoped to the pipeline's own compartment doesn't cover it. — **Covered**: §5.1 Nuance box.
14. Functions authenticates as an OCI resource principal under ordinary IAM policy — no pull secret; OKE's pull path is governed by the Kubernetes API, which has no native OCI-principal concept, so it needs an explicit `imagePullSecret` instead. — **Covered**: §5.2.
15. Yes — the 100,000-image-per-repository cap exists independently of storage, so the team would eventually be blocked by image count alone. As images grow larger, the 500 GB storage quota becomes the binding constraint sooner, potentially before the count cap is reached. — **Partial**: the lesson gives both quota figures and states the general direction (large images hit storage first), but doesn't walk through this specific counterfactual ("no storage limit at all") the way the question poses it.

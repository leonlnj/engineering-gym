## Questions

1. A team has fully automated Jenkins pipelines, yet releases are still "thrown over the wall" to a separate ops group. Which pillar is missing, and why doesn't CI/CD alone supply it? _(DevOps overview · production-reasoning)_
2. How does a Kubernetes-manifest artifact in a deployment pipeline end up pointing at the exact image the build just produced? Name the mechanism end to end. _(artifact wiring · exam-ready)_
3. Your build needs an API key but the security team forbids credentials in any file in the repo. What build-spec mechanism do you use, and what IAM must exist for it to work? _(secrets in builds · exam-ready)_
4. Compliance requires that the *identical* image tested in staging is what runs in production. Which twelve-factor factor is this, and what pipeline design property guarantees it? _(12-factor parity · production-reasoning)_
5. Pipeline events are being published, but no human ever receives an email when a deployment fails. The topic exists. What is missing? _(notifications · exam-ready)_
6. A prod deployment needs a human sign-off before rollout and a bake period after the canary traffic shift. Which deployment-pipeline stage types implement each? _(pipeline control stages · exam-ready)_
7. What does a service mesh provide that plain OKE Services and an ingress controller do not — and what is the current way to get a mesh on OCI? _(service mesh · exam-ready)_
8. A containerized app writes its logs to `/var/log/app.log` inside the container. Which factor does this violate, and what should it do instead on OKE? _(12-factor logs · exam-ready)_
9. In an OKE blue-green deployment, where does the "standby" version actually live, and what physically happens at the traffic switch? _(blue-green mechanics · production-reasoning)_
10. When is Code Editor the right tool over a local VS Code + OCI CLI setup — and when is it clearly the wrong one? _(Code Editor selection · production-reasoning)_
11. What role does OCIR play between the build pipeline and the deployment pipeline, and how does the build authenticate its push to it? _(OCIR interplay · exam-ready)_
12. Your organisation already runs GitHub Actions well. What would justify *staying* there instead of migrating to OCI DevOps, and what would you give up by staying? _(adoption trade-off · production-reasoning)_

## Answer key

1. DevOps — the culture where one team owns a service commit-to-production. CI/CD automates the mechanics of delivery; it cannot merge the ownership split. — **Covered**: §1.1 defines DevOps as the operating culture distinct from pipeline tooling.
2. The build computes the tag and exports it (`exportedVariables`); the deliver stage maps `outputArtifacts` to project artifact resources; the manifest artifact carries `${IMAGE_TAG}` with placeholder substitution at deploy time. — **Covered**: §4.3–§4.4 and walkthrough step 6.
3. `vaultVariables` — the spec references a Vault secret OCID; the pipeline's dynamic group needs a `read secret-family` policy. — **Covered**: §4.1 policy example + §4.3.
4. Factor X (dev/prod parity). Guaranteed because release = re-deploying the same immutable, hash-tagged image artifact — the pipeline substitutes a tag, never rebuilds. — **Covered**: §3.1 row X, §5 closing paragraph.
5. A subscription on the topic. The project publishes events to the topic, but delivery to a person requires subscriptions (email, Slack, etc.) on it. — **Partial**: §4.1 covers the required topic and what gets published, but never mentions that subscriptions are what turn a topic into delivered notifications.
6. Approval stage for the sign-off; wait stage for the bake period. — **Covered**: §4.5 names both stage types with their purpose (briefly).
7. Service-to-service concerns: mutual TLS, retries, traffic splitting via sidecar proxies — cluster ingress handles north-south, a mesh handles east-west. Current OCI answer: run Istio on OKE; the managed OCI Service Mesh is retired. — **Covered**: §1.2 note + Practical Limits (retirement dated and sourced).
8. Factor XI — logs as an event stream. Write to stdout and let the platform (OCI Logging) collect it. — **Covered**: §3.1 row XI.
9. Standby runs as a parallel deployment of full production capacity; the switch redirects user traffic from active to standby (and rollback is switching back). — **Partial**: §4.5 covers the strategy semantics accurately, but the OKE-specific mechanics (where standby lives — e.g. a second namespace — and what implements the switch) are not described.
10. Right: quick edits to repos/build specs with zero local setup, Functions development in-console, workshops. Wrong: primary IDE or anything long-running — small fixed home, session timeouts. — **Covered**: §6.1–6.2.
11. OCIR is the hand-off point: the build pushes the image (deliver stage), the deployment pulls it via the manifest reference. The push authenticates via resource principal (dynamic group), not stored credentials. — **Covered**: §4.4, §5 step 4.
12. Staying is justified by ecosystem depth (actions/plugins) and existing team skill; you give up resource-principal auth (no stored cloud credentials) and zero pipeline infrastructure to operate. — **Covered**: final Practical Limits bullet states both sides.

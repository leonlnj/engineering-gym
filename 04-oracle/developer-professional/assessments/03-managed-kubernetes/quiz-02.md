## Questions

1. A team on a Basic cluster wants workload identity for fine-grained pod IAM starting tomorrow. Can they get it by paying more while staying on Basic? _(tier feature-gate vs. price · production-reasoning)_
2. Can a single Enhanced cluster run a managed node pool for a stateful database and a virtual node pool for a bursty API side by side, or must a cluster commit to one node type entirely? _(node type mixing · production-reasoning)_
3. A team wants to run Calico on their OKE virtual-node pool for advanced network policy enforcement. What happens? _(virtual node networking restriction · exam-ready)_
4. A pod on a virtual node needs a scratch directory shared between two of its containers. Can it declare two separate `emptyDir` volumes to keep their writes isolated? _(virtual node volume limits · exam-ready)_
5. What happens to a generated kubeconfig's ability to authenticate against an OKE cluster if the engineer who ran `create-kubeconfig` leaves the company and their OCI account is deactivated? _(kubeconfig credential lifecycle · production-reasoning)_
6. Before OSOK existed as an OKE add-on, how would a team have provisioned an Autonomous Database for a workload running on the cluster? _(OSOK value proposition / origin · production-reasoning)_
7. In the HPA-to-node scale-up walkthrough, what concrete condition does the Cluster Autoscaler actually watch for before it decides to act? _(scaling walkthrough mechanics · exam-ready)_
8. A Basic-cluster team runs an in-place node pool upgrade. What manual step do they have to perform that an Enhanced-cluster team gets automatically? _(node cycling / Enhanced-only feature · exam-ready)_
9. The first objection to in-place upgrades is "what happens to pods running mid-cycle?" How does the lesson's answer to that differ between Basic and Enhanced clusters? _(upgrade objection pre-emption · production-reasoning)_
10. OSOK's credentials are documented to be stored as what kind of Kubernetes object, and why not baked directly into the controller image? _(OSOK credential mechanics · exam-ready)_
11. A private-endpoint cluster needs "a network path into the VCN" before `kubectl` can reach it. The lesson names bastion, VPN, and FastConnect as options — does it explain how any of them actually gets `kubectl` traffic to the API server? _(private endpoint connectivity mechanism · production-reasoning)_
12. Name one dial OKE gives you that isn't just "the concept of a managed control plane" shared by any cloud's managed Kubernetes offering. _(OKE-specific vs. generic managed k8s · production-reasoning)_

## Answer key

1. No — virtual nodes, workload identity, granular add-on management, and node cycling are entirely unavailable on Basic regardless of budget; this is a feature gate, not a metering difference. — **Covered**: §2.1 table and its Nuance ("a team that needs serverless node pools has no Basic-tier path to them at all").
2. Yes — a single Enhanced cluster commonly runs a stable managed-node pool for stateful/DaemonSet-dependent workloads alongside a virtual-node pool absorbing bursty, stateless traffic. — **Covered**: §3.5, closing sentence.
3. Rejected in effect — only VCN-Native pod networking is supported on virtual nodes; third-party CNI plugins including Calico are explicitly unsupported. — **Covered**: §3.3.
4. No — only one `emptyDir` volume is allowed per pod spec on a virtual node, alongside `ConfigMap` and `Secret`; two separate `emptyDir`s is not a supported configuration. — **Covered**: §3.3 ("a narrow set of ephemeral volume types (`emptyDir` capped at one per pod, `ConfigMap`, `Secret`) are allowed").
5. Not addressed. — **Missing**: §4.2 explains that the kubeconfig mints short-lived tokens via the OCI CLI rather than embedding a static credential, but never connects this to the personal-account-departure risk — a pattern the lesson does flag elsewhere (§6.3's OSOK credential, and Module 02's `ocirsecret`) but doesn't apply back to kubeconfig-based cluster access itself.
6. A separate `oci` CLI call or Terraform run, entirely outside the cluster's own deployment flow. — **Covered**: §6.1.
7. The scheduler finding no node with enough free CPU/memory to place the new pods, which sit `Pending` — the Autoscaler watches for exactly that unschedulable-pod condition. — **Covered**: §5.4, steps 2–3.
8. A Basic cluster requires manually cordoning and draining each node before its replacement; Enhanced automates that cycling. — **Covered**: §5.2.
9. Node cycling — an Enhanced-only capability — automatically cordons and drains each node before replacing it so workloads reschedule onto already-upgraded nodes; Basic clusters lack node cycling and require the same cordon/drain performed manually before each replacement. — **Covered**: §5.2.
10. A Kubernetes `Secret`, so the credential isn't hardcoded into the controller image and can be rotated independently of a controller release. — **Covered**: §6.3.
11. Not addressed. — **Partial**: §4.1 names bastion host, VPN, and FastConnect as connectivity options but doesn't unpack the mechanism of any of them — e.g. whether a bastion serves as an SSH jump host you tunnel `kubectl` through, or something else. A reader knows the option exists but not how to actually execute it.
12. The Basic/Enhanced tier split, the serverless virtual-node option, and IAM-native governance of the whole cluster are all OKE-specific dials layered on top of the universal "managed control plane" concept. — **Covered**: §1.2, closing paragraph.

## Resolved

2026-07-23 — Both gaps closed after lesson edits:
- **Q5** (kubeconfig credential-lifecycle risk): added as a Nuance in §4.2, explicitly connecting back to the identical pattern already named for `ocirsecret` (Module `02`) and OSOK's credential (§6.3) — a kubeconfig generated under a personal identity breaks silently on that account's deactivation.
- **Q11** (bastion/VPN/FastConnect mechanism): added to §4.1 — a bastion opens a short-lived managed SSH session, a VPN is a persistent IPSec tunnel, FastConnect is a dedicated private circuit; framed as a durability-and-throughput trade-off among the three.

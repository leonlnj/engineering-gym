## Resolved

2026-07-23 — All four gaps (Q1/Q2/Q3/Q4) closed after verification and lesson edits:
- **Q1** (table/prose consistency): the §2.1 table's node-cycling row now reads "Node cycling during upgrades (in-place path only — see *Scaling and Upgrades*)" instead of the unqualified original — a skimming reader now sees the scope right in the table.
- **Q2** (add-on management artifact): added to §2.1 — Enhanced allows enabling/disabling/pinning/configuring essential add-ons individually; Basic runs the same add-ons by default but silently reverts any customization that conflicts with Oracle's reconciliation, confirmed against Oracle's cluster-add-ons docs.
- **Q3** (OSOK credential options): added to §6.3 — an `auth_type` setting supports resource principal, instance principal, and OKE workload identity alongside the dedicated-IAM-user path, confirmed against the OSOK project's own installation docs; explicitly tied back to the Enhanced-only workload-identity feature named in §2.1, closing a connection the lesson had left open since that section.
- **Q4** (Cloud Shell credential risk): added to §4.3's existing Nuance — Cloud Shell authenticates as the same personal IAM identity as the console, so a kubeconfig generated there carries the identical credential-lifecycle risk as one generated from a local CLI install.

7. Sketch a permission configuration for an agent operating on a cluster, and state the principle behind which actions go where. _(permission gates · operate)_
8. Why is a plan-before-act mode valuable on a non-trivial change? _(plan mode · augment)_
9. Why must an agent be able to run your tests/build, and what is it doing when it can't? _(ground truth · augment)_
10. Why is an agent acceptable as an interactive pair-programmer but a hazard wired into an unattended pipeline? _(autonomy bound · operate)_
11. An agent confidently calls a Helm value that doesn't exist. Why does this happen, and what is the only reliable defence? _(hallucination · augment)_
12. The loop is `while True` ending only when "the model decides it's done." What stops it from running forever if the model never decides? _(loop bounds · operate)_
13. An agent takes 30 loop iterations to fix a bug. Why is that materially more expensive than one model call, and how does the cost scale with steps? _(loop cost · operate)_

## Answer key

1. The **model** is the stateless next-token predictor — it can only read and emit text, never runs anything. The **harness** (Claude Code, Cursor, Copilot agent mode) is the program that owns the loop: calls the model, parses tool requests, executes real tools, enforces permissions, feeds results back. The model proposes; the harness disposes — so all real effects go through the harness. — **Covered**: §1.1.
2. Autocomplete predicts the next few characters you were already typing; an agent takes a stated goal, decides for itself what to read/run, and produces a multi-step change you review. The shift is typing → delegating. — **Covered**: intro + §1.1.
3. The model predicts tokens that happen to form a structured **tool-use block** (tool name + arguments) instead of prose; the harness parses it, runs the real command, appends the output. It is token prediction, not agentic choice — which is why "decides" is misleading. — **Covered**: §1.1.
4. Same schema mechanism (lesson 02 §4) run in reverse: there the filled schema was the *answer's shape*; here it is an *action* the harness executes. Only what you do with the filled schema differs. — **Covered**: §1.1.
5. The agent explores the repo itself — listing dirs, grepping, opening files it judges relevant — to build the working memory it needs instead of you pasting files in. So it reconstructs context like a new engineer would. — **Covered**: §2.2.
6. Superpower: it finds the context it needs to make a coherent change in an unfamiliar repo. Bottleneck: every file/output consumes the token budget, so a large codebase overflows the window and the agent silently reasons from a partial view. — **Covered**: §2.2 + §5.2 + §7.
7. `allow` read-only/safe (Read, `git status`, `kubectl get`), `ask` writes/network (`kubectl apply`, `Edit`), `deny` destructive (`kubectl delete`, `rm -rf`). Principle: read freely, gate anything that writes/deletes/reaches the network so one bad decision can't quietly do damage. — **Covered**: §3.1.
8. You catch a misunderstanding while it's still a paragraph of plan, not after the agent edited fifteen files down the wrong path — two minutes spent instead of twenty. — **Covered**: §3.2.
9. Without the ability to run the build/test/read the real error, the agent reasons in the dark and guesses; running them lets it check its own work and turn a plausible-looking change into a verified one. — **Covered**: §3.2 Note + §4 step 2.
10. Non-determinism (it samples) means a fix that works once may not reproduce, and an early misread compounds — tolerable when a human reviews each result, a real hazard unattended. — **Covered**: §5.2 + §7 (bridge to lesson 05).
11. It generates plausible-looking code, and a non-existent function/flag/Helm value is plausible — worst for fast-moving tools and internal libraries it never trained on. Defence: verify by running; confidence is not correlated with correctness. — **Covered**: §5.1 + §5.2 Nuance.
12. A real harness bounds the loop with a **step budget** (and often wall-clock/cost ceilings), so a confused agent that would otherwise thrash forever is capped and surfaced — the same guardrail instinct as permission gates, applied to *how long* it runs. — **Missing** (as found): the loop was shown as unbounded `while True` with no cap mentioned anywhere.
13. Each iteration re-sends the *entire accumulated* context (no memory between calls), so input reprocessed grows each step and the total is **quadratic** in step count, not linear — e.g. ~110k input tokens for a 10-step task vs ~2k for one call. Prompt caching mitigates the stable prefix. — **Partial** (as found): §2.2 covered window *consumption* but never the compounding token cost.

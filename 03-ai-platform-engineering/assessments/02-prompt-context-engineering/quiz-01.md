# Assessment 01: Prompt & Context Engineering — Building the Model's Working Memory

> Generated by lesson-eval (coverage mode) on 2026-06-30. Source spec: STUDY-PLAN.md entry for `02`.

## Questions

1. Why are message roles (`system` / `user` / `assistant`) *not* a security boundary? Tie it to the mechanism. _(roles · augment)_
2. If everything is flattened into one token sequence, how does the model tell the system prompt from the user's text? _(chat template · augment)_
3. You have an 8K-token window and lots of relevant material. Why is "include everything relevant you can find" wrong even *before* you hit the limit? _(budget discipline · operate)_
4. Given many retrieved documents, where in the window do you place the single most relevant one, and why? _(placement · operate)_
5. A long chat is about to overflow; dropping the oldest turns makes the model contradict decisions made earlier. What's the better strategy, and what does it cost? _(history compaction · operate)_
6. Why does chain-of-thought actually improve accuracy — mechanically, not "it thinks harder"? _(prompt technique · augment)_
7. Distinguish prompt engineering from context engineering and state the relationship between them. _(confusable terms · augment)_
8. How does declaring a JSON schema *force* valid output rather than just politely request it? _(constrained decoding · operate)_
9. What does schema-constrained output cost, and when would you deliberately *not* use a rigid schema? _(structured-output trade-off · operate)_
10. Name the two practices that make grounding reliable and why each matters. _(grounding · operate)_
11. Grounding is the strongest practical hallucination defence — why is it still not a correctness guarantee? _(grounding limits · operate)_
12. Your system prompt + few-shot examples are large and identical on every call. What feature reduces the cost/latency of resending them, and what must be true to benefit? _(cost lever · operate)_
13. Sketch the cost of a single call given a token budget. Why isn't cost symmetric with size? _(billable resource · operate)_

## Answer key

1. Roles are just text marked with special control tokens in one flattened stream — the model learned what the delimiters mean; they are not isolated channels. So data pasted into a `user` message can still smuggle instructions (prompt injection). — **Covered**: §1.1.
2. The API wraps each message in **control tokens** via the **chat template**, and the model learned during training what those delimiter tokens mean. — **Covered**: §1.1.
3. Padding the window with marginal content buries the facts that matter ("lost in the middle") and costs more per token/latency; the goal is the *smallest* sufficient context, not the largest that fits. — **Covered**: §2.2 + §2.3.
4. At a high-attention **edge** (start or end), because models attend most reliably there and weakest to the middle — the same fact can be read or ignored based only on position. — **Covered**: §2.3.
5. **Rolling summarisation**: replace the oldest verbatim turns with a compact recap preserving decisions/constraints, keep recent turns verbatim. Cost: the summary is a lossy extra model call (latency + tokens) that can drop a detail later turns need. — **Covered**: §2.4.
6. Each generated token conditions the next (lesson 01); writing intermediate reasoning builds a context that leads to a better-supported conclusion than jumping straight to the answer. Cost: more output tokens/latency. — **Covered**: §3.2.
7. Prompt engineering = wording one instruction well (a subset); context engineering = assembling everything that occupies the window (the superset). A perfect prompt can't rescue a window missing the key fact. — **Covered**: §3 (table).
8. **Constrained decoding**: a mask between logits and sampler zeroes every token that would break the schema at each step, so only schema-valid tokens are reachable — invalid output is impossible, not merely improbable. Cost: the schema must be expressible as an enforceable grammar. — **Covered**: §4.1.
9. Cost: a little flexibility — a rigid schema can clip a nuanced answer. Don't use one where a human reads the output (allow prose); reserve rigid schemas for machine consumers. — **Covered**: §4.2 + §8.
10. (1) Explicitly permit abstention ("say you don't know") so it doesn't fill gaps with a guess; (2) require citations to the supplied material so wrong answers are auditable. — **Covered**: §5.2.
11. The model can still misread, over-generalise, or blend supplied facts with training priors; grounding shifts the odds and makes errors checkable, but is not a proof of correctness. — **Covered**: §5.2 Nuance.
12. **Prompt caching**: the model's computed KV state for the unchanging prefix is retained server-side, so repeated calls skip recomputing it — cheaper and faster. Requires the prefix to be byte-identical and placed first. — **Missing** (as found): prompt caching was not mentioned.
13. e.g. 6,500 input + 1,500 output tokens; priced per million with **output several times dearer than input**, so a few output tokens can dominate the bill — cost is not proportional to raw token count. — **Partial** (as found): budgets were token-only; the "billable" framing was never costed in money.

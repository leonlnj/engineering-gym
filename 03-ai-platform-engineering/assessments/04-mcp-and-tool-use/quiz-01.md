## Questions

1. A tool call is a "four-step round-trip," but only two steps are messages on the wire. Which two are not, and why does naming that matter? _(round-trip mechanics · operate)_
2. Why is a tool's `description` "effectively a prompt"? _(tool declaration · augment)_
3. Why does MCP collapse N×M integrations to N+M — what exactly gets standardised? _(integration problem · operate)_
4. Define host, client, and server, and map each to what happens when you run `claude mcp add k8s …`. _(architecture · operate)_
5. You want to give an agent your cluster's alerting runbook. Tool, resource, or prompt — and why? _(capability choice · operate)_
6. Why is a resource *not* just a read-only tool? _(confusable terms · operate)_
7. Which transport do you build a new remote MCP server on, and what is the real story with SSE? _(transports/currency · operate)_
8. What is sampling, and why does the spec put a human in the loop for it? _(sampling · augment)_
9. You tell the model in its prompt never to delete deployments, but a `delete_deployment` tool is exposed. Can it still delete? Where is the real boundary? _(security · operate)_
10. Sketch the credential scoping for a read-only triage server and state the principle. _(least privilege · operate)_
11. Credential layer vs middleware: what does each bound, and why do you want both? _(defence in depth · operate)_
12. A guardrail gateway unions every backend's tools — say 200 of them — behind one endpoint. What's the downside, and how do you manage it? _(catalogue cost · operate)_
13. Your MCP server runs as a remote HTTP service. How does it know *who* is calling and authorize them — and how does that differ for a stdio server? _(inbound auth · operate)_
14. A tool call fails — the `kubectl` command errors or the pod doesn't exist. What gets sent back to the model, and what does the model do with it? _(error path · operate)_

## Answer key

1. Steps 1, 2, 4 are messages; **step 3 (the harness running the real function) produces no message** — the model is idle while local code executes. Naming it stops the reader hunting for a missing message and shows precisely the one step the model can never perform itself. — **Covered**: §1.2.
2. The model chooses and fills tools based on the name/description/schema text, so a vague description yields wrong or skipped calls — the description is read like a prompt. — **Covered**: §1.1.
3. A common interface: a system exposes capabilities once as an MCP server, and any compliant agent consumes them with no bespoke glue — so integrations add up (N+M) instead of multiplying (N×M). — **Covered**: §2.
4. Host = the app the user talks to (Claude Code); client = one managed connection inside the host per server; server = the separate process holding the backend creds. `claude mcp add k8s` makes the host spin up one client to that k8s server. — **Covered**: §3.1.
5. A **resource** — it's read-only reference data the host loads into context to ground the model, always-useful, and read-only is the lower-risk default. (A tool if it should be fetched only on demand to save budget.) — **Covered**: §3.2 + §3.3.
6. A tool is something the **model** decides to call mid-reasoning to *act*; a resource is data the **host** loads into context to *inform*, before/around reasoning. Exposing data as a `get_config` tool wastes a model turn and adds an action to its decision space. — **Covered**: §3.2 Nuance.
7. **Streamable HTTP** for new remote servers. HTTP+SSE was the original remote transport, now deprecated/superseded by Streamable HTTP (which uses SSE under the hood for streaming) — recognise SSE-only servers as legacy, don't target them. — **Covered**: §3.4 (web-confirmed current).
8. Sampling reverses the flow: the *server* asks the *host* to run an LLM completion (`sampling/createMessage`), so a server adds AI without its own key/model. Human-in-the-loop because an untrusted server is spending your model, context, and bill — the host lets the user review/edit/deny. — **Covered**: §3.5.
9. Yes, it can — a model can be talked out of instructions, and an exposed tool can be called regardless of prose. The real boundary is the server's **credential**: enforce in the access layer, not the prompt. — **Covered**: §6.2 Nuance.
10. A ClusterRole granting `get`/`list` on `pods`, `pods/log`, `events` and nothing that mutates; the server runs with that scoped token. Principle: least privilege — expose the narrowest actions and scope the credential to only those. — **Covered**: §6.1.
11. Credentials set the static outer boundary (what the token can reach at all); middleware does a per-call runtime check inside that boundary (sanitise args, redact output, verify state, allow/deny/audit). Both = defence in depth — even a permitted call can be refused by middleware. — **Covered**: §7 intro + §7.3.
12. The whole catalogue (names/descriptions/schemas) is sent to the model every request, so it spends the context budget and a large, similar set degrades tool selection. Manage it by exposing a curated, namespaced surface and hiding tools a host shouldn't call. — **Partial** (as found): §7.2 namespaced tools but never stated the catalogue's context cost or selection degradation.
13. A remote (Streamable HTTP) server authenticates the caller via MCP's **OAuth 2.1** flow (server = resource server; client presents an access token per request); a **stdio** server needs none — the OS process boundary is the authentication and it reads backend creds from its environment. This caller identity is distinct from the scoped service credential the server uses outbound. — **Missing** (as found): §6 covered only the outbound credential. — *web-confirmed the OAuth framework exists.*
14. The harness returns a `tool_result` with the same `tool_use_id` but `is_error: true` carrying the error text; the model reads it as context and can retry with a fix, try another tool, or report the failure. Happy and error paths share the same channel — only the flag differs. — **Missing** (as found): the lesson showed only the success path.

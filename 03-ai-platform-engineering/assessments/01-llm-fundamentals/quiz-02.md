## Questions

1. Why does the tokenizer use *sub-word* pieces rather than whole words or single characters? Give the failure each of the two extremes would cause.  _(tokenization design · operate)_
2. You must send a ~4,000-word runbook plus expect a ~600-word answer. Roughly how many tokens is that, and what's the rule of thumb you used?  _(token↔cost math · operate)_
3. In "the pod crashed because **it** ran out of memory," walk through how attention's query/key/value vectors resolve what `it` refers to.  _(attention mechanics · operate)_
4. Heads and layers both "repeat" attention. What does each axis actually buy you — what's the difference between width and depth here?  _(confusable terms · operate)_
5. The output projection `Wout` is often the embedding matrix transposed ("weight tying"). Why would you tie them rather than learn a separate output matrix?  _(why / efficiency · operate)_
6. After the model has ~100,000 raw logits, why run a softmax at all before sampling — what does it give you that the raw logits don't?  _(inference mechanics · operate)_
7. Temperature and top-p both affect randomness. Mechanically, how does each reshape the next-token distribution, and can you use both at once?  _(sampling taxonomy · operate)_
8. A teammate says "just tell the model our new API in chat and it'll remember it next week." Why is that wrong, and what are the two real options for giving it that knowledge?  _(training vs inference · operate)_
9. You stuff 100K tokens of context in and the model still misses a key fact. Why might a *bigger* window not help, and where should you place must-use facts?  _(context limits / trade-off · operate)_
10. Cosine similarity scores closeness by angle, not distance. Why use direction rather than vector length, and what do scores of 0 and −1 mean?  _(embeddings geometry · operate)_
11. Greedy decoding picks the top token every step. Why is it "nearly" — not fully — deterministic, and why isn't even temperature 0 byte-for-byte reproducible?  _(non-determinism mechanics · operate)_
12. The stored embedding for "bank" is identical in "river bank" and "central bank." Why is that a problem, and what part of the architecture fixes it?  _(context-free embeddings · operate)_

## Answer key

1. Whole-word vocabularies can't represent any word unseen in training (typos, identifiers, new terms become unknowable blanks); single characters make sequences punishingly long and force the model to relearn spelling every time. Sub-words (BPE) are the compromise — common words are one token, rare ones split into reusable pieces, and *any* string is representable. — **Covered**: §1.1.
2. ~1,000 tokens ≈ 750 words, so 4,000 words ≈ ~5,300 tokens of input and ~600 words ≈ ~800 tokens of output, billed separately (input + output). — **Covered**: §1.1 (1k≈750 words) + §1.2 (4k words ≈ 5,300 tokens; input/output billed separately).
3. Each token derives a query (what it seeks), a key (what it offers), a value (what it passes on). `it`'s query is dot-scored against every key; `pod` scores highest (e.g. 0.71), so the softmaxed weights make `it`'s updated representation a blend dominated by `pod`'s value — the model has, in effect, bound `it` to `pod`. — **Covered**: §3.2.
4. **Heads** run in parallel *within* a layer — each with its own Q/K/V projections tracking a different relationship (reference, agreement, topic), concatenated. **Layers** stack *in sequence* — each refines the previous layer's already-enriched vectors, local structure first then higher-order meaning. Width = many relationships per pass; depth = reasoning in passes. — **Covered**: §3.3.
5. Tying reuses one `vocab × dim` matrix for both directions, deleting a second large parameter block (e.g. ~410M weights for 100k × 4,096) and forcing the "meaning" and "scoring" views of a token to agree, which also mildly regularises. — **Covered** (after this run's §4.1 add; **as found** it was **Partial** — the dual use was stated but not the param-saving why).
6. Raw logits are unbounded real numbers; softmax maps them to a proper probability distribution (each 0–1, summing to 1) so the sampler can draw a token by probability. Without it there's nothing well-formed to sample from. — **Covered**: §4.1.
7. **Temperature** scales the logits before softmax — low sharpens toward the top token, high flattens so unlikely tokens get a real chance. **Top-p (nucleus)** keeps only the smallest set of tokens whose probabilities sum to *p* and samples within it, cutting the long tail. They compose — top-p trims the tail, temperature reshapes what's left. — **Covered**: §4.2.
8. Inference runs on **frozen weights** — the model doesn't learn from your chat, remember users, or update itself; it also has a knowledge cutoff. The two real options: **fine-tuning** (continue the train-time nudge loop on a targeted dataset to change behaviour) or, for facts, **RAG** (inject the needed text into the context at inference time). — **Covered**: §6.1 + §2.3 Note; precise RAG-vs-fine-tune line deferred to lesson 07.
9. A bigger window only raises the *ceiling* on what you can pass, not how well the model uses it — the documented "lost in the middle" effect means facts buried mid-context are frequently missed. Put must-use material at the start or end of the window, and never assume "it's in the context" means "it'll be used." — **Covered**: §5.3.
10. Direction is used so that magnitude (intensity/length) doesn't distort the comparison — two vectors pointing the same way are "similar" regardless of length. Cosine 1 = same direction (highly similar), 0 = perpendicular (unrelated), −1 = opposite. — **Covered**: §2.2.
11. Greedy is only "nearly" deterministic because floating-point non-associativity on GPUs, batching with other requests, and silent provider-side model updates can shift which token wins; for the same reason even temperature 0 is "low variance," not byte-reproducible. — **Covered**: §4.2 + Nuance.
12. A raw embedding is context-free — the row for "bank" is identical regardless of surrounding words — but meaning depends on context. **Attention** (the Transformer) fixes it by mixing information between positions so each token's representation absorbs its neighbours (river vs central). — **Covered**: §3.1.

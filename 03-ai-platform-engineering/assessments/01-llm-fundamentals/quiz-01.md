# Assessment 01: LLM Fundamentals — What the Model Actually Computes

> Generated by lesson-validation (coverage mode) on 2026-06-30. Source spec: STUDY-PLAN.md entry for `01`.

## Questions

1. Why can you not write `assertEqual` against an LLM call, and what replaces equality testing? _(non-determinism · operate)_
2. A model miscounts the r's in "strawberry." Explain mechanically why, and why it's a tokenization artefact rather than a reasoning failure. _(tokenization artefacts · operate)_
3. You're choosing a temperature for (a) structured data extraction and (b) brainstorming names. Which direction for each, and why? _(sampling trade-off · operate)_
4. Context window vs KV-cache: what *kind* of thing is each, and if the logits are recomputed every step, how can caching possibly help? _(confusable terms · operate)_
5. Why does each successive turn of a long chat get slower and more expensive? _(context budget cost · operate)_
6. Why is an embedding *not* a hash of the token, and what property does a hash deliberately destroy that an embedding needs? _(embeddings: why · operate)_
7. The model confidently (and wrongly) describes a service you deployed last week. Why does this happen, what is the fix, and what does that fix cost? _(cutoff → RAG trade-off · operate)_
8. When a token is sampled, what carries over to the next step and what is recomputed from scratch? _(autoregression · operate)_
9. What is the join key between the tokenizer and the embedding table, and why does its numeric value carry no inherent meaning? _(vocab↔embedding contract · operate)_
10. Attention produces a *weighted blend* of value vectors with no built-in notion of order. How does the model distinguish "pod crashed" from "crashed pod"? _(attention mechanism · operate)_
11. After the transformer layers produce one vector for the last position, how does that single vector become ~100,000 logits? _(connecting artifact · operate)_
12. Given a 128K-token model that must hold system prompt + RAG docs + history + user message + response, how do you reason about fit, and what happens on overflow? _(context budgeting · operate)_

## Answer key

1. Sampling makes the call non-deterministic — the same prompt can return different tokens, and even temperature 0 is only "low variance" (FP non-associativity, batching, silent model updates). Reliability comes from evals over datasets, not equality checks. — **Covered**: §4.2 Nuance, §8 bullet 1, Summary.
2. The model sees opaque sub-word tokens (e.g. `ernetes`), not individual characters, so it never "saw" the letters to count. It's an artefact of tokenization, not flawed reasoning. — **Covered**: §1.2.
3. Low/near-zero temperature for extraction and code (focused, repeatable); higher temperature for brainstorming (varied, exploratory, more error-prone). Match the dial to the task. — **Covered**: §4.2 + §8 bullet 2.
4. The window is a *logical* token-count limit (a rule, lives nowhere); the KV-cache is a *physical* store in GPU memory holding past tokens' keys/values. Caching works because past tokens' K/V never change in a causal model (representation depends only on earlier tokens) — only the logits change each step and those are recomputed, not cached. — **Covered**: §5.2 (strongest passage).
5. Conversation "memory" is an illusion — all prior turns are resent as input every call, so input grows each turn; attention cost grows ~quadratically and the KV-cache linearly. — **Covered**: §5.1 + §8 bullet 3.
6. A hash is *designed* to scatter — similar inputs land nowhere near each other. An embedding is a *learned* lookup whose geometry encodes similarity (related tokens end up close). Relatedness is grown by training, not built in. — **Covered**: §2.3.
7. Frozen weights → a knowledge cutoff; the model has no record of post-training or private facts and generates a plausible (hallucinated) continuation. Fix: inject the facts into the context at inference time (RAG). Costs: spends context budget, adds retrieval latency, and a wrong-chunk retrieval grounds a confident wrong answer; benefits include freshness and traceability. — **Covered**: §6.2 + Nuance.
8. Nothing carries over but the appended text. The model runs a fresh forward pass over the now-longer sequence and recomputes a brand-new logit vector; no goal/plan/belief is tracked between steps. — **Covered**: §3.3.
9. The vocabulary ID (row number) is the join key: the tokenizer assigns it and the embedding table has exactly one row per vocab entry in the same order. The integer is just a position — `23532` is not "more" than `8002`. — **Covered**: §1.3 + §2.1.
10. Attention alone is order-blind (a weighted sum is permutation-invariant). Order is injected as a **positional encoding** added to each token's embedding (or a position-dependent rotation, RoPE) before the first layer, so the same token at different positions enters as distinguishable input. — **Missing** (as found): positional encoding was never introduced; attention was shown only as an order-agnostic blend.
11. The last position's enriched hidden vector is multiplied by an **output/unembedding projection** (one row per vocab entry, often the embedding matrix transposed — weight tying) to produce the ~100k-long logit vector. — **Partial** (as found): §4.1 asserted logits are "emitted" but never showed the projection or the tie-back to the embedding matrix.
12. Budget the window like a pod memory limit: sum system prompt + retrieved docs + history + user message + reserved response tokens against the hard cap; on overflow the oldest/least-relevant content must be dropped or summarised. — **Covered**: §5.1 (128K worked budget).

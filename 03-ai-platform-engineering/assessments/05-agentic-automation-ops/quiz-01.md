## Answer key

1. **suggest** (or *approve* at most) — **reversibility** dominates: an action you cannot trivially undo earns the lowest autonomy regardless of how routine it seems. — **Covered**: §1.2 + the reversibility Note ("if the agent gets this exactly wrong, can I recover, and how fast?").
2. Non-determinism and hallucination make an unattended agent unsafe; the goal is **bounded autonomy** — agents handling toil inside guardrails strong enough that their worst possible action is tolerable. — **Covered**: intro + §8.
3. **IaC generation** — the output lands in a pull request, so existing review and CI gates catch errors before anything is applied. — **Covered**: §2.1.
4. The diff is the *real* effect the tool will apply, not the agent's paraphrase of its intent; the human reviews the concrete verb (`1 to change, 0 to destroy` vs `destroy`), turning "trust the agent" into "review the diff." — **Covered**: §3.1.
5. They enforce limits independent of the agent's judgement or how it was prompted; even a fully hijacked or injected agent cannot exceed its RBAC scope — the credential, not the prompt, is the limit. — **Covered**: §3.2 + §6.2.
6. `resourceNames: [payments]` — it scopes the `patch` verb to one deployment, so even if the agent is tricked into targeting another deployment the API server rejects the call. — **Covered**: §3.2.
7. The read path is wide open because reading is safe and powers most of the value; the write path is narrow, gated, and scoped. The system contains misbehaviour by design rather than by trusting the agent — that structural asymmetry is the takeaway. — **Covered**: §4.2.
8. The human approves the single rollback (one decision); the agent does all gathering, correlation, and execution around it. Strip the gate and it becomes an agent that rolls back production on probabilistic judgement — fine nine times, an outage the tenth. — **Covered**: §5.
9. An ops agent constantly reads attacker-influenceable text (logs, tickets, annotations) and cannot reliably separate data it reads from instructions to follow. The defence is the credential + approval layer — an injected agent still cannot exceed its scope or skip a gate. — **Covered**: §6.2.
10. Hard limits — `MAX_STEPS`, `MAX_TOKENS`, `WALL_CLOCK` — that abort and escalate. A plan-act-observe loop can self-extend, burn tokens, and hammer APIs, so bounding keeps a confused run cheap rather than catastrophic. — **Covered**: §6.1.
11. Every mutating action needs a gate, a policy, or scoped credentials around it, so automating more of ops means building and maintaining more guardrails — there is no free autonomy. — **Covered**: §7.
12. An OPA/Gatekeeper Rego rule rejecting the agent's user on a protected namespace. The lesson shows exactly this, but **as found** it used the pre-OPA-1.0 partial-rule syntax `deny[msg] { ... }`; OPA 1.0 (GA Jan 2025) requires `deny contains msg if { ... }` (or `import rego.v1`). — **Covered (stale)**: §3.2.
